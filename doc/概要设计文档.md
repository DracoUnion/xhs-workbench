# 小红书 AI 工作台 概要设计文档（SDD）

> 版本：v1.0　|　日期：2026-09-08　|　配套文档：[prd.md](./prd.md)
> 技术栈：**FastAPI（Python） + React（TypeScript） + OpenAI API + PostgreSQL + Redis + Celery + Playwright + ADB**

---

## 一、文档说明

### 1.1 编写目的

依据《小红书 AI 工作台 PRD》（`doc/prd.md`），将原「Claude Code + Obsidian + Playwright/ADB」的松耦合脚本编排，收敛重构为一套**独立 Web 应用**。本文档描述系统的概要设计，作为详细设计、代码开发与验收的基线。

### 1.2 设计范围

| 范围 | 说明 |
|------|------|
| ✅ 包含 | 三条主链路（需求发现 / 产品制作 / 内容获客）、Agent 编排引擎、数据模型、API、调度、风控、部署 |
| ⭕ 不包含 | 小红书 App 逆向、绕过风控的批量 API 调用（沿用 PRD：真机 + 真账号 + 随机延迟） |
| 🔧 替换 | Obsidian 看板 → React 管理台；本地 Obsidian 目录 → PostgreSQL + 文件对象存储 |

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 千帆 | 小红书商家后台「千帆数据中心」，提供 8 个榜单入口 |
| 主 Agent | 协调层：拆解任务、调度子 Agent、处理异常、汇总结果 |
| 子 Agent | 单职能 Agent（采集 / 分析 / 生成 / 审查），可独立启停 |
| Skill | 内容生产模板规范（SKILL.md），固化标题/正文/图片规则 |
| 标 | 对标，即竞品参考对象 |
| Run | 一次 Agent 任务的完整执行记录（含断点） |
| 检查点 | Run 中可暂停/恢复/人工介入的位置 |

## 二、设计目标与设计原则

### 2.1 设计目标

1. **替代手工闭环**：将「刷榜 → 选品 → 采店 → 做货 → 做内容 → 发布」全链路自动化，人只做方向决策与最终验收。
2. **稳定 7×24 运行**：单机可部署，长任务可断点续跑、异常自恢复。
3. **可沉淀可复用**：Skill 与子 Agent 提示词全部落库并可管理，支撑内容模板无限沉淀。

### 2.2 设计约束

- 采集走**真机 + 真浏览器 + 真人节奏**（PRD 5.4），不调批量 API。
- 单个手机 / 单个浏览器上下文**串行独占**（全局设备锁），杜绝并发抢设备。
- AI 生成必经**审查 Agent / 人工审核点**，防止「自己审自己」。

### 2.3 设计原则

| 原则 | 落地方式 |
|------|---------|
| 确定性优先 | 评分、去重、校验等纯逻辑用代码实现，不用 AI；AI 只做理解/生成 |
| Agent 可配置 | Agent 提示词、工具白名单、模型均存库，管理台可改，不发版 |
| 一次一处 | 单篇拆解、日更生成严格遵守「一次只处理一个」 |
| 中间态可追溯 | 所有结果落库，人工判断不被自动更新覆盖 |

## 五、模块设计

### 5.0 核心通用模块：Agent 编排引擎

所有业务能力都以「子 Agent + 工具集」的形式实现，由编排引擎统一驱动。

#### 5.0.1 子 Agent 定义（入库，可配置）

| 字段 | 说明 |
|------|------|
| `agent_defs` 表 | 每个子 Agent 一条：`key`（如 `qianfan_collector`）、系统提示词、工具白名单、默认模型、超时 |
| 工具 | 每个工具为「Pydantic 参数模型 → JSON Schema」+ 一个 Python handler |
| Run | 一次执行的实例，记录会话消息、检查点、状态 |

#### 5.0.2 执行循环（Celery Task 内）

```
1. 从 DB 恢复/初始化 Run 上下文
2. loop:
     a. 调 OpenAI chat.completions(tools=[...])，得到 tool_calls 或最终回答
     b. 命中工具 → 路由到对应 Python handler → 结果 append 进 messages
     c. 模型要求暂停（遇到检查点/审核点）→ 状态置 BLOCKED，WebSocket 通知人
     d. 达成终止条件 → 写入结论，状态置 DONE
3. 全程异常捕获：手机/浏览器未响应 → 恢复子程序 → 重试（指数退避）
4. 断点：会话消息 JSONB 落库，Worker 重启后从中断处续跑
```

#### 5.0.3 检查点与人工审核点

| 类型 | 触发人 | 行为 |
|------|--------|------|
| `AUTO` 检查点 | 采集量级、去重、校验类 | 自动放行，计数进 Run 报告 |
| `REVIEW` 审核点 | 采集校验不通过、Skill 上线、内容包出稿 | Run 阻塞，前端任务中心出现审核卡，人批/退 |
| `MANUAL` 人工点 | 购买对标资料、付款、Codex 开发 | 标记状态，等待人线下完成后确认继续 |

#### 5.0.4 工具清单（权威注册表）

| 工具 key | 归属 | 说明 |
|----------|------|------|
| `qianfan.collect_ranking` | 千帆采集 | 采集单个榜单项（入口×页码） |
| `account.score` | 评分 | 按 PRD 4.1.3 计算评分（纯函数） |
| `adb.open_profile/store` | 手机 | 打开主页/店铺 |
| `adb.open_product` / `adb.copy_share_link` | 手机 | 遍历商品、复制短链 |
| `web.collect_product_detail` | 商品采集 | 按短链采集商品详情与图 |
| `account.analyze` | 账号分析 | 逐号产出品类/价格/形态/复杂度结论 |
| `web.mobile_search_keyword` | 对标采集 | 手机 App 搜索关键词产出短链 |
| `web.collect_note` | 对标采集 | 图文/视频笔记采集 |
| `transcribe.video` | 对标采集 | 视频转写 |
| `note.analyze` | 单篇拆解 | 一次一篇结构拆解 |
| `template.cluster` | 模板聚类 | 聚类 + 产出模板草案 |
| `content.generate` | 日更生成 | 读取产品 + Skill 生成内容包 |
| `content.review` | 内容审查 | 对照产品资料与 Skill 复核 |
| `whitelist/blacklist.*` | 通用 | 关键词去重、商品去重 |

> 幂等与去重：同产品下所有关键词共用去重记录（PRD 4.3.4），由 `dedup` 工具统一判重。

### 5.1 模块一：需求发现（找需求）

#### 5.1.1 千帆榜单采集子 Agent

- **入口配置**（库表 `ranking_sources`）：阅读/引流/热卖/成交榜 × 优秀内容/优秀账号，共 8 个入口，每个入口独立启停、独立页码进度。
- **节奏**：每入口默认最多 20 页，翻页后随机等待 60~90s（`risk_config` 可调）。
- **采集字段**：来源、排名、笔记标题、账号名、阅读量区间、商品点击率、支付转化率、成交金额区间。
- **落库**：`rankings` 表；同一账号多次上榜时聚合计分。

#### 5.1.2 账号评分（确定性纯函数，非 AI）

严格实现 PRD 4.1.3：

```
需求证据分 = 成交分×0.5 + 支付转化分×0.35 + 阅读分×0.15
可信度加成 = 1 + (上榜天数/10)×0.25 + (进榜类型数/4)×0.25
低粉加成   = 1 + (1000-粉丝)/1000×0.6   # 仅粉丝<1000
总分 = 需求证据分 × 可信度加成 × 低粉加成
```

- 区间映射表（成交金额、支付转化率）存库为配置，便于调参。
- 分值明细（各分项得分）落 `account_metrics`，看板可追溯。

#### 5.1.3 手机端店铺遍历子 Agent（ADB 链路）

```
1. 取高价值账号 userId → adb 打开主页（mobile-gateway）
2. 识别「店铺」入口 → 点击进入
3. 逐个打开商品 → 复制分享短链 → 记录 → 返回店铺
4. 全部商品完成后结束；每动作后确认页面状态，异常自动恢复
```

- **设备独占**：全局 Redis 锁 `device:phone`，同一时刻仅一个 Run 占用手机。
- **恢复**：锁屏→亮屏解锁；卡死→back/重启 App；分享面板未弹→重试。
- 短链先入临时表，供电脑端采集。

#### 5.1.4 商品详情采集与校验

- 短链 → Playwright 打开 → 采集：标题、价格、可见销量、规格、详情文案、全部图片。
- **校验**（任一不过则不入分析，并告警）：
  - 商品链接数 == 本地保存详情数；
  - 每篇图片数量完整且可打开。
- 二次去重：同 userId × 商品 id 唯一。

#### 5.1.5 账号分析与方向汇总

- **账号分析子 Agent**：逐号产出主营品类、商品数、价格区间、最高销量商品、产品形态（资料/模板/测试/教程）、交付复杂度、是否低粉高销。
- **方向汇总（主 Agent）**：按「品类 × 产品形态」聚类账号，方向状态机：

```
观察中 → 升温（多账号同形态） → 已验证(有完整商品详情支撑) → [降温/放弃]
```

- 方向结论、支撑账号、价格范围、最高销量全部落 `directions` / `direction_accounts`，供看板与产品制作模块消费。

### 5.2 模块二：产品制作（做产品）

#### 5.2.1 虚拟资料路径

| 步骤 | 系统支撑 | 人工点 |
|------|---------|--------|
| 购买对标资料 | 生成采购清单、待办卡 | 人工付款（`MANUAL` 检查点） |
| AI 整理分析 | 资料入库 → 文档解析（PDF/Word/Excel → 文本）→ 整理子 Agent 产出「内容梳理」
| 确定结构 | 结构模板编辑器（目标用户/核心问题/形态/交付清单） | 人确认 |
| 按模块制作 | 制作子 Agent 逐模块产出，人逐模块验收 | 人验收 |
| 最终验收 | 自动化检查：表格错位/链接可用/文件完整性/上手体验清单 | 人终验 |

- 文档解析用 `docx`/`pdf`/`xlsx` 解析库接入 `ingest` 工具；资料包统一存 `data/products/<product_id>/materials/`。

#### 5.2.2 网站/小程序/工具路径

- 保留 PRD 的「需求整理 → 图片原型 → UI 还原 → 逻辑开发 → 逐步验收」五步，落地为产品子实体上的阶段推进：
  - 原型与页面清单独存 `design_docs` 表；
  - 代码仓库地址、构建产物挂在 `products.build` 字段；
  - 逐步验收 = 运行检查（截图）+ 人确认清单。
- 平台说明：本系统只做**任务承载与进度/验收管理**，实际编码可手工/交由外部编码工具完成（作 `MANUAL` 资产，不做强依赖）。

### 5.3 模块三：内容获客（做内容）

#### 5.3.1 产品分析子 Agent

- 读取产品全部原始资料（intro、价格、截图、说明、客户反馈）→ 整理：
  - `产品总览`（是什么/给谁用/解决什么问题/价格/功能/适用/效果/购买方式）；
  - `资料索引`（按模块组织的可引用文件清单）。
- 产出需人确认（价格、功能、效果等核心信息），确认后才进入关键词阶段。

#### 5.3.2 关键词布局

- 7 维度（品类/人群/痛点/场景/卖点/购买顾虑/替代方案）产出 10~20 词，落 `keywords` 表。
- 每词配置：采集篇数（默认 5-10）、是否 A-Z 扩展（仅 2-3 核心词）、是否采集评论。

#### 5.3.3 对标采集（手机 + 浏览器）

| 源 | 方式 | 落库 |
|----|------|------|
| 手机 App 搜索 | adb 输入关键词 → 打开笔记 → 复制短链（复用设备锁） | `note_links` 临时表 |
| 图文笔记 | Playwright：标题/正文/话题/作者/互动数据/封面+内页图 | `notes` / `note_images` |
| 视频笔记 | 原视频 + 封面 + 关键帧 + 本地转写语音稿 | `notes` / `note_frames` / `transcripts` |

- 去重：同一产品下所有关键词共用去重记录（`dedup` 工具）；A-Z 扩展词采集后并回主词。

#### 5.3.4 单篇拆解子 Agent

- **一次只拆一篇**；产出：标题公式、正文结构与分段逻辑、封面/内页分工、开头钩子类型、互动数据特征（收藏高/评论高/无明显特征）。
- 标记 `analyzed=true`，形成 `note_analyses`，供聚类消费。

#### 5.3.5 模板聚类子 Agent

- 按内容角度/标题结构/正文骨架聚类；视觉相似但目的不同的分开。
- **同一类至少 3 篇对标支撑**才生成模板草案；
- 产出 `模板说明.md`（研究结论）→ 存 `templates` 表，标记「草稿」。

#### 5.3.6 Skill 制作与存储

- 将模板草案固化为 **SKILL.md**，存 `skills` 表（支持在线编辑 + 版本历史 `skill_versions`）。
- 三要素强制齐全：
  1. **产品资料引用**：允许引用的具体文件白名单，Agent 只能从中取产品事实；
  2. **文案规范**：标题公式/正文分段/话题策略/禁用说法；
  3. **图片规范**：封面设计、内页分工、图片来源（截图/排版）。
- **测试要求**：新 Skill 先由日更 Agent 出 1 个完整内容包，走完整审查 + 人确认后才设为 `active`。

#### 5.3.7 日更生成与内容审查（职责分离）

- **日更生成子 Agent**：一次一个产品 + 一份 Skill；读产品总览 → 读 Skill 指定文件 → 按步骤产出标题/正文/话题/封面/内页 → `content_packages`。
- **内容审查子 Agent**（独立定义、独立部署语义，与生成 Agent 分离）：重新读产品资料 + 同一 Skill，检查事实准确性、是否符合 Skill、图片文字清晰度、标注位置；不过则退回改稿重审（限 N 轮）。
- **人工审核开关** `skills.review_policy = manual | auto`：新 Skill 默认 manual，稳定后可 auto。

## 六、数据设计

### 6.1 ER 概览（文本）

```
users ─┬─< agent_runs <─ agent_defs
       └─< reviews
ranking_sources ─< rankings ─< accounts
accounts ─< account_metrics

### 6.2 核心表定义

| 表 | 关键字段 | 说明 |
|----|---------|------|
| `users` | id, username, password_hash, role, whitelist<(token) | 登录与权限 |
| `agent_defs` | key, name, system_prompt, tool_keys[], model, timeout | 子 Agent 定义 |

| `ranking_sources` | key, name, page_max, delay_min/max | 8 个榜单入口配置 |
| `rankings` | source, rank, note_title, account_id, read_range, click_rate, pay_rate, amount_range | 榜单数据 |
| `accounts` | user_id, nickname, fans, score, metrics_id | 账号与总分 |
| `account_metrics` | evidence_score, trust_bonus, low_fans_bonus, breakdown(JSONB) | 评分明细 |
| `products` | id, direction_id, account_id, title, price, sales, spec, desc, images[], form(unclear:资料/模板/工具), status | 商品实体 |
| `directions` | id, name, category, form, status(观察中/升温/已验证/降温/放弃), evidence | 产品方向 |
| `keywords` | id, product_id, word, pages_target, a_to_z, collect_comments, collected_count | 关键词配置与进度 |
| `notes` | id, product_id, kw, note_id, title, body, author, interactions(JSONB), media_type, source_link | 对标笔记 |
| `note_analyses` | note_id, title_formula, structure, hook_type, cover_rule, interaction_feature | 单篇拆解 |
| `templates` | id, product_id, cluster_key, supported_count, draft_md | 模板聚类草稿 |
| `skills` | id, product_id, md, files_whitelist[], rules(JSONB), status(draft/testing/active), review_policy | SKILL.md |
| `skill_versions` | id, skill_id, md, created_by, note | 版本历史 |
| `content_packages` | id, skill_id, title, body, topics[], images[], status(draft/reviewing/approved/rejected) | 内容包 |

### 7.1 REST API 总览（前缀 `/api/v1`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` / `refresh` | JWT 登录 |

| GET/PATCH | `/settings/risk` `/settings/agents` | 风控参数 / Agent 配置 |

### 7.2 WebSocket 实时通道

- 路径：`/ws/tasks?user_id=xxx`
- 事件：`run.progress`（当前步骤/耗时/日志）、`run.blocked`（等待人工）、`run.done/failed`、`device.lock`（手机占用状态）。
- 前端据此驱动任务中心与看板刷新，后台轮询仅作兜底。

### 7.3 关键 API 示例：发起采集

```
POST /api/v1/rankings/tasks
{ "source": "hot_sale_excellent_account", "page_max": 20, "delay_range": [60, 90] }
→ 202
{ "run_id": 128, "mode": "async", "eta": "..." }

WS 事件：run.progress {run_id:128, step:"ranking_page", page:3/20}
WS 事件：run.blocked {run_id:128, type:"REVIEW", payload:"采集校验未通过..."}
POST /api/v1/review-points/{id} { "action":"retry" }  → 任务继续
```

## 八、任务调度与并发设计

| 需求 | 设计 |
|------|------|
| 长任务执行 | Celery 任务 = 一个 Agent Run；长任务用 `acks_late` + DB 断点，非 `task.retry`（避免重跑到一半） |
| 7×24 定时 | Celery Beat：每日定时启动榜单采集、日更生成 |
| 反风控节奏 | `risk_config` 每节点延迟区间 + 随机抖动；翻页/点击/下拉统一走 `delay` 工具 |
| 设备独占 | Redis 锁 `device:phone`（手机）、`device:browser`（浏览器）；拿不到锁则排队 |
| 串行约束 | 千帆采集与对标采集共用浏览器锁；店铺遍历独占手机锁 |
| 失败恢复 | 异常分类：可重试（网络/页面未就绪）指数退避；需人工（校验不过/风控）→ 置 `blocked` |
| 并发上限 | 单机默认 `--concurrency=1`（避免多 Worker 抢设备），多机通过 Redis 锁扩展 |

## 九、安全与风控设计

1. **鉴权**：JWT（短时 access + 刷新 token）；管理台单人/小团队场景，支持 IP 白名单可选。
2. **密钥管理**：OpenAI Key、店铺 Cookie 等敏感项经环境变量 / 服务端配置存取，不落前端。
3. **采集风控**（沿用 PRD 5.4）：真机 + 真账号 + 随机延迟 60~90s；浏览器上下文独立持久化（`data/browser-contexts/`）；连续任务含随机空闲。
4. **隔离**：千帆采集与对标采集使用独立浏览器 Context / Profile，互不污染登录态。
5. **审计**：`agent_runs` / `reviews` 全量留存，人工判断与 AI 结论分列，不被覆盖。

## 十、部署设计

### 10.1 单机 Docker Compose（推荐场景）

```
xhs-workbench/
├─ backend/            # FastAPI 应用 + celery worker
├─ frontend/           # React 构建产物，nginx 托管
├─ services/
│  ├─ browser/         # Playwright 容器（chromium）
│  └─ transcriber/     # 可选：faster-whisper 转写服务

- 宿主需连接安卓真机：宿主 `adb server` + `adb connect <device>`，后端手机适配层通过 adb 协议访问；或手机网络 ADB（`adb connect <IP:port>`）。
- 环境变量：`OPENAI_API_KEY`、`DATABASE_URL`、`REDIS_URL`、`ADB_SERIAL`、`JWT_SECRET`、`ADMIN_USER`/`ADMIN_PASS`。

### 10.2 进程拓扑

```
docker:  frontend(nginx:80)  backend(uvicorn)  worker(celery)  beat  redis  postgres  browser  [transcriber]
host:    adb server ↔ 安卓真机（USB/WiFi）
```

## 十三、风险与应对

| 风险 | 影响 | 技术应对 |
|------|------|---------|
| 平台页面结构变化 | 千帆/商品/笔记采集失效 | 采集选择器集中配置（CSS/XPATH 存库），适配层单独可灰度回滚 |

| 生成内容偏离 | 内容质量问题 | Skill 固化 + 审查 Agent 职责分离 + 人工审核开关 |
| 账号风控 | 采集受限 | 真机真账号 + 随机延迟 + 设备锁串行 + 独立浏览器上下文 |
| OpenAI 调用失败/超时 | Agent 中断 | 指数退避重试 + 断点续跑 + 模型可降级配置 |
