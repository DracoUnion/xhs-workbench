# 小红书 AI 工作台产品需求文档（PRD）

> 基于「南墙」90 天消耗 406 亿 Token 搭建的小红书虚拟产品自动化工作流整理


## 一、产品概述

### 1.1 产品定位

小红书 AI 工作台是一套**以 AI 驱动的虚拟产品全自动运营系统**，覆盖从需求发现、产品制作到内容获客的完整商业闭环。系统通过多 Agent 协同、手机+电脑双端配合，实现数据采集、分析、内容生成和发布的自动化。

### 1.2 产品目标

- **核心目标**：将小红书虚拟产品从「需求发现 → 产品制作 → 内容获客」的完整链路实现自动化，让操盘手从重复劳动中解放，专注于方向选择与最终验收。
- **量化指标**：支撑每月 1～2 万元被动收入，单个方向从需求发现到产品上线周期控制在 3～7 天内。

### 1.3 产品价值

- **效率提升**：AI 自动扫描 8 个榜单入口、每日覆盖数百条数据，替代人工刷榜
- **决策依据**：从「凭感觉选品」升级为「数据驱动的需求验证」
- **规模化复制**：内容 Skill 机制让优质内容结构可沉淀、可复用


## 二、目标用户

| 用户类型 | 描述 | 核心诉求 |
|---------|------|---------|
| **独立操盘手** | 个人或小团队运营小红书虚拟产品的自由职业者 | 降低人工投入，提升选品和内容产出效率 |
| **虚拟产品创业者** | 销售模板、教程、素材包等虚拟资料的卖家 | 快速验证需求方向，批量产出产品 |
| **内容创作者** | 需稳定产出小红书图文内容的博主 | 建立可持续的内容生产流水线 |

## 四、功能模块详述

### 模块一：需求发现（找需求）

#### 4.1.1 功能描述

AI 自动扫描小红书千帆数据中心的 8 个榜单入口，采集账号和商品数据，通过评分模型筛选高价值账号，再深入店铺采集商品详情，最终汇总出已验证的市场需求方向。

#### 4.1.2 数据采集

| 采集项 | 说明 |
|--------|------|
| **榜单入口** | 阅读榜、引流榜、热卖榜、成交榜，每类分「优秀内容」和「优秀账号」 |
| **采集深度** | 每个入口最多采集 20 页，每页间隔 60-90 秒 |
| **榜单数据字段** | 榜单来源、排名、笔记标题、账号名称、阅读量区间、商品点击率区间、支付转化率区间、成交金额区间 |

#### 4.1.3 账号评分模型

**总分 = 需求证据分 × 可信度加成 × 低粉加成**

**需求证据分** = 成交分×50% + 支付转化分×35% + 阅读分×15%

| 成交金额区间 | 成交分 | 支付转化率 | 转化分 |
|-------------|-------|-----------|-------|
| 0～1000元 | 0.10 | 0～5% | 0.10 |
| 1000～5000元 | 0.30 | 5%～15% | 0.30 |
| 5000～1万元 | 0.60 | 15%～25% | 0.55 |
| 1万～5万元 | 1.00 | 25%～50% | 0.80 |
| - | - | 50%～70% | 0.95 |
| - | - | 70%～90% | 1.00 |

**可信度加成** = 1 + (上榜天数÷10)×25% + (进入榜单类型数÷4)×25%

**低粉加成** = 1 + (1000 - 粉丝数) ÷ 1000 × 0.6（粉丝＜1000时生效）

#### 4.1.4 手机端店铺遍历

因电脑端无法稳定进入小红书店铺，系统通过 ADB 控制安卓真机完成：

1. 根据 userId 拼接主页链接，通过 ADB 在手机端打开
2. 识别「店铺」入口并点击进入
3. 逐个打开商品，复制分享短链
4. 返回店铺继续，直至全部商品处理完成
5. 每个动作后确认页面状态，异常时自动恢复

#### 4.1.5 商品详情采集与校验

电脑端根据手机获取的分享短链，采集完整商品信息：

- 商品标题、价格、可见销量
- 商品规格与详情文案
- 商品页面全部图片

**采集校验**（不通过则不进入分析）：
- 商品链接数 = 本地保存的详情数
- 每篇商品图片数量完整且可正常打开

#### 4.1.6 账号分析与方向汇总

账号分析子 Agent 逐号分析：
- 主营品类、商品数量、价格区间
- 最高销量商品、产品形态（资料/模板/测试/教程等）
- 交付复杂度、是否存在低粉高销

主 Agent 将品类和产品形态相近的账号归为同一方向，标记状态：
- **观察中**：证据不足以形成结论
- **升温**：多个账号出现相近商品形态
- **已验证**：有完整商品详情支撑
- **降温**：未继续看到商品机会
- **放弃**：无法交付或不值得研究

#### 4.1.7 Obsidian 看板展示

- 当日完成账号数和商品数
- 最终形成的产品方向列表
- 每个方向的支撑账号、价格范围、最高销量
- 当前市场状态与下一步建议


### 模块二：产品制作（做产品）

#### 4.2.1 功能描述

将已验证的需求方向转化为可交付的产品。根据产品形态不同，分为「虚拟资料」和「网站/小程序/工具」两条路径。

#### 4.2.2 虚拟资料制作流程

1. **购买对标资料**：从闲鱼、淘宝、拼多多购买同方向成品资料（需人工付款）
2. **AI 整理分析**：逐份读取资料，梳理内容、适用对象、交付方式，找出重复内容、独有内容和未解决问题
3. **人确定结构**：确定目标用户、核心问题、产品形态（模板/教程）、交付文件清单
4. **按模块制作**：AI 逐模块产出，人逐模块验收，发现问题即时修改
5. **最终验收**：检查表格错位、链接可用性、文件完整性、用户上手体验

#### 4.2.3 网站/小程序/工具开发流程

1. **需求整理**：将需求资料交给 Codex，整理目标用户、核心需求、使用场景和页面清单
2. **图片原型**：Codex 生成高保真 UI 图片原型，人确认视觉和功能布局
3. **UI 还原**：按原型 1:1 写出 UI 代码，每完成一页与原型对照验收
4. **逻辑开发**：逐项实现业务逻辑，页面间跳转、数据流转、提交反馈等
5. **逐步验收**：Codex 按真实用户路径逐步操作，每步截图检查，通过后再继续


### 模块三：内容获客（做内容）

#### 4.3.1 功能描述

围绕已完成的產品，建立标准化的内容生产流水线，从关键词布局到日更内容生成全自动化。

#### 4.3.2 产品分析

产品分析子 Agent 读取全部原始资料（产品介绍、价格、截图、使用说明、客户反馈等），整理为：
- **产品总览**：产品是什么、给谁用、解决什么问题
- **资料索引**：按模块组织的可引用文件清单

需人检查确认：价格、功能、适用范围、使用效果、购买方式、案例评价等核心信息准确无误。

#### 4.3.3 关键词布局

从品类、人群、痛点、场景、卖点、购买顾虑、替代方案 7 个维度，产出 10-20 个研究关键词。

**关键词配置项**：
- 每个词采集篇数（首次 5-10 篇）
- 是否开启 A-Z 扩展（仅对 2-3 个核心词开启）
- 是否采集评论

#### 4.3.4 对标采集（手机+电脑配合）

**手机端**：在小红书 App 搜索关键词，打开图文/视频笔记，复制分享短链

**电脑端**：
- 图文笔记：保存标题、正文、话题、作者、互动数据、封面及全部内页图
- 视频笔记：保存原视频、封面、抽取关键帧、本地语音模型转写语音稿
- 去重机制：同一产品下所有关键词共用去重记录

#### 4.3.5 单篇拆解

单篇拆解子 Agent 逐篇分析图文笔记：
- 标题公式（如「人群＋具体问题＋结果」）
- 正文结构与分段逻辑
- 封面与内页的分工
- 开头钩子类型
- 互动数据特征（收藏高/评论高/无明显特征）

**关键原则**：一次只拆一篇，避免多篇混拆导致结论失真。

#### 4.3.6 模板聚类

模板聚类子 Agent 基于拆解结果进行聚类：
- 内容角度、标题结构、正文骨架相近的归为一组
- 视觉相似但目的不同的分开处理
- **同一类至少 3 篇对标支撑**才能生成模板草案
- 产出：模板说明.md（研究结论，尚不可直接用于日更）

#### 4.3.7 内容 Skill 制作（关键环节）

将模板草案转化为可执行的 **SKILL.md**，需人和 AI 共同完成：

**Skill 必须包含**：
1. **产品资料引用**：列出允许引用的具体文件，Agent 只能从这些文件取产品事实
2. **文案规范**：标题公式、正文分段逻辑、话题策略、禁用说法
3. **图片规范**：封面设计、内页分工、图片来源（截图/排版）、图片 Skill 调用

**测试要求**：Skill 完成后先让日更 Agent 生成 1 个完整内容包，检查文案准确性、图片稳定性，问题修复后再上线。

#### 4.3.8 日更生成与内容审查

**日更生成子 Agent**：
- 一次只处理一个产品和一份 Skill
- 读取产品总览 → 读取 Skill 指定文件 → 按步骤生成标题/正文/话题/封面/内页
- 产出完整内容包（文字+图片）

**内容审查子 Agent**（与生成 Agent 分离，防止自我通过）：
- 重新读取产品资料和同一份 Skill
- 检查产品事实准确性、文案是否符合 Skill、图片文字清晰度、标注位置正确性
- 未通过则退回日更 Agent 修改，改完重审

**人工审核开关**：新 Skill 初期开启人工审核，AI 审完后人工过一遍；稳定后可关闭。


## 五、技术架构

### 5.1 硬件环境

| 组件 | 说明 |
|------|------|
| **电脑** | Mac（推荐）或 Windows，运行 Obsidian + 浏览器 |
| **手机** | 安卓真机，登录小红书账号，通过 ADB 控制 |
| **浏览器** | Mac 用 Ego，Windows 用 Playwright，保持独立采集空间 |

### 5.2 AI 工具链

| 工具 | 用途 |
|------|------|
| **Claude Code / Codex / Hermes / OpenClaw** | 主 Agent 及子 Agent 运行环境 |
| **Codex** | 网站/小程序/工具开发（图片原型 → UI → 逻辑） |
| **本地语音模型** | 视频语音稿转写 |

### 5.3 数据存储

- **Obsidian**：工作台看板、配置、采集数据、生成内容统一存储
- 目录结构：`00-基础 / 01-产品 / 02-关键词 / 03-采集结果 / 04-生成内容 / 工具 / 面板 / agents`

### 5.4 风控策略

- 使用真实安卓手机 + 真实账号，非 API 批量调用
- 每个动作后随机等待 60-90 秒
- 连续 7×24 小时运行未触发风控

## 七、非功能需求

### 7.1 稳定性
- 手机锁屏、App 卡住、分享面板未打开时，主 Agent 自动尝试恢复
- 采集中断后已保存内容保留，恢复后继续
- 商品数或图片数不齐时，不进入分析阶段

### 7.2 可扩展性
- 子 Agent 可独立新增/替换（如视频拆解流程可独立接入）
- Skill 机制支持无限内容模板沉淀

### 7.3 可维护性
- 所有中间结果写入 Obsidian，进度可追溯
- 人工判断、计划和验证结果保留，不被自动更新覆盖
- 配套脚本、配置、面板代码、Agent 提示词以附件形式提供

## 九、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 小红书平台规则变化 | 采集/发布受限 | 商品下架换产品，店铺被封换店铺，运营方式随平台调整 |
| AI 生成内容质量不稳定 | 内容偏离预期 | Skill 机制固化规则 + 内容审查 Agent 把关 + 人工审核开关 |
| 手机端操作异常 | 采集中断 | 主 Agent 异常恢复机制 + 分步确认 |
| 账号风控 | 无法采集数据 | 真机+真账号+随机延迟，已验证 7×24 小时无风控 |


> **说明**：本 PRD 基于南墙「90 天消耗 406 亿 Token」的实际运营经验整理，完整脚本、配置、Obsidian 面板代码及子 Agent 提示词见附件压缩包。
